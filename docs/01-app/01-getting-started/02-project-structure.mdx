### 路由文件

添加 `page` 即可暴露一个路由;`layout` 用于页头、导航、页脚等共享 UI;`loading` 用于骨架屏;`error` 用于错误边界;`route` 用于 API。

| [`loading`](/docs/app/api-reference/file-conventions/loading)                 | `.js` `.jsx` `.tsx` | 加载 UI                      |
| [`not-found`](/docs/app/api-reference/file-conventions/not-found)             | `.js` `.jsx` `.tsx` | 未找到 UI                    |

### 嵌套路由

文件夹定义 URL 片段,文件夹嵌套即片段嵌套。任意层级的 layout 都会包裹其子片段。当片段中存在 `page` 或 `route` 文件时,该路由才对外公开。

| 路径                        | URL 模式        | 说明                          |
| --------------------------- | --------------- | ----------------------------- |
| `app/layout.tsx`            | —               | 根布局包裹所有路由            |
| `app/blog/layout.tsx`       | —               | 包裹 `/blog` 及其子路由       |
| `app/page.tsx`              | `/`             | 公开路由                      |
| `app/blog/page.tsx`         | `/blog`         | 公开路由                      |
| `app/blog/authors/page.tsx` | `/blog/authors` | 公开路由                      |

### 动态路由

用方括号给路由片段参数化。`[segment]` 表示单个参数,`[...segment]` 表示捕获所有(catch-all),`[[...segment]]` 表示可选捕获所有。参数值通过 [`params`](/docs/app/api-reference/file-conventions/page#params-optional) 属性获取。

| 路径                            | URL 模式                                                             |
| ------------------------------- | -------------------------------------------------------------------- |
| `app/blog/[slug]/page.tsx`      | `/blog/my-first-post`                                                |
| `app/shop/[...slug]/page.tsx`   | `/shop/clothing`、`/shop/clothing/shirts`                            |
| `app/docs/[[...slug]]/page.tsx` | `/docs`、`/docs/layouts-and-pages`、`/docs/api-reference/use-router` |

### 路由组与私有文件夹

使用路由组 [`(group)`](/docs/app/api-reference/file-conventions/route-groups#convention) 组织代码而不影响 URL;使用私有文件夹 [`_folder`](#private-folders) 存放不可路由的文件。

| 路径                            | URL 模式    | 说明                                      |
| ------------------------------- | ----------- | ----------------------------------------- |
| `app/(marketing)/page.tsx`      | `/`         | 分组名不会出现在 URL 中                   |
| `app/(shop)/cart/page.tsx`      | `/cart`     | 在 `(shop)` 内共享布局                    |
| `app/blog/_components/Post.tsx` | —           | 不可路由;适合放 UI 辅助组件              |
| `app/blog/_lib/data.ts`         | —           | 不可路由;适合放工具函数                  |

### 并行路由与拦截路由

这两类特性服务于特定的 UI 模式,例如基于插槽(slot)的布局或模态路由。

`@slot` 用于父布局渲染的命名插槽。拦截模式可以在不改变 URL 的情况下,在当前布局内渲染另一条路由,比如在列表上方以模态框形式展示详情。

| 模式(文档)                                                                                | 含义                 | 典型用例                                 |
| ------------------------------------------------------------------------------------------- | -------------------- | ---------------------------------------- |
| [`@folder`](/docs/app/api-reference/file-conventions/parallel-routes#slots)                 | 命名插槽             | 侧边栏 + 主内容                          |
| [`(.)folder`](/docs/app/api-reference/file-conventions/intercepting-routes#convention)      | 拦截同级             | 以模态框预览兄弟路由                     |
| [`(..)folder`](/docs/app/api-reference/file-conventions/intercepting-routes#convention)     | 拦截上一级           | 把父级的子路由以浮层打开                 |
| [`(..)(..)folder`](/docs/app/api-reference/file-conventions/intercepting-routes#convention) | 拦截上两级           | 深层嵌套浮层                             |
| [`(...)folder`](/docs/app/api-reference/file-conventions/intercepting-routes#convention)    | 从根目录拦截         | 在当前视图中展示任意路由                 |

## 组织你的项目

Next.js 对项目文件的组织与存放方式**不作规定**。但它提供了若干特性来帮助你组织项目。

### 组件层级

特殊文件中定义的组件会按特定层级渲染:

- `layout.js`
- `template.js`
- `error.js`(React 错误边界)
- `loading.js`(React Suspense 边界)
- `not-found.js`(用于"未找到" UI 的 React 错误边界)
- `page.js` 或嵌套的 `layout.js`

<Image
  alt="Component Hierarchy for File Conventions"
  srcLight="/docs/light/file-conventions-component-hierarchy.png"
  srcDark="/docs/dark/file-conventions-component-hierarchy.png"
  width="1600"
  height="643"
/>

组件在嵌套路由中递归渲染,也就是说某个路由片段的组件会嵌套在其父片段组件**内部**。

### 共存(Colocation)

在 `app` 目录中,嵌套文件夹定义路由结构。每个文件夹代表一个路由片段,映射到 URL 路径中的对应片段。

不过,即便路由结构通过文件夹定义,只要片段中尚未加入 `page.js` 或 `route.js` 文件,该路由就**无法被公开访问**。

<Image
  alt="A diagram showing how a route is not publicly accessible until a page.js or route.js file is added to a route segment."
  srcLight="/docs/light/project-organization-not-routable.png"
  srcDark="/docs/dark/project-organization-not-routable.png"
  width="1600"
  height="444"
/>

而且,即使路由已经公开,发送到客户端的也只有 `page.js` 或 `route.js` **返回的内容**。

<Image
  alt="A diagram showing how page.js and route.js files make routes publicly accessible."
  srcLight="/docs/light/project-organization-routable.png"
  srcDark="/docs/dark/project-organization-routable.png"
  width="1600"
  height="687"
/>

这意味着**项目文件**可以**安全地共存**于 `app` 目录的路由片段内,而不会被意外变成可路由内容。

<Image
  alt="A diagram showing colocated project files are not routable even when a segment contains a page.js or route.js file."
  srcLight="/docs/light/project-organization-colocation.png"
  srcDark="/docs/dark/project-organization-colocation.png"
  width="1600"
  height="1011"
/>

> **须知**:虽然你**可以**把项目文件放在 `app` 里,但并非**必须**。如果你愿意,也可以[把它们放在 `app` 目录之外](#store-project-files-outside-of-app)。

### 私有文件夹

给文件夹名加下划线前缀即可创建私有文件夹:`_folderName`。

这表示该文件夹是私有实现细节,路由系统不应将其纳入考量,从而把**该文件夹及其所有子文件夹**排除在路由之外。

<Image
  alt="An example folder structure using private folders"
  srcLight="/docs/light/project-organization-private-folders.png"
  srcDark="/docs/dark/project-organization-private-folders.png"
  width="1600"
  height="849"
/>

由于 `app` 目录中的文件[默认就可以安全共存](#colocation),私有文件夹并非共存的必要条件。但它仍有用处:

- 把 UI 逻辑与路由逻辑分开。
- 在整个项目乃至 Next.js 生态中统一内部文件的组织方式。
- 在代码编辑器中排序和分组文件。
- 避免与未来 Next.js 文件约定产生命名冲突。

> **须知**:
>
> - 这虽不是框架约定,但你也可以用同样的下划线模式把私有文件夹之外的文件标记为"私有"。
> - 若想创建以下划线开头的 URL 片段,可以用 `%5F`(下划线的 URL 编码形式)作文件夹前缀:`%5FfolderName`。
> - 如果你不使用私有文件夹,建议了解 Next.js 的[特殊文件约定](/docs/app/getting-started/project-structure#routing-files),避免意外的命名冲突。

### 路由组

用圆括号包裹文件夹名即可创建路由组:`(folderName)`。

这表示该文件夹仅用于组织目的,**不应计入**路由的 URL 路径。

<Image
  alt="An example folder structure using route groups"
  srcLight="/docs/light/project-organization-route-groups.png"
  srcDark="/docs/dark/project-organization-route-groups.png"
  width="1600"
  height="849"
/>

路由组的用途:

- 按站点板块、意图或团队组织路由,例如营销页面、管理后台等。
- 在同一路由片段层级启用嵌套布局:
  - [在同一片段中创建多个嵌套布局,包括多个根布局](#creating-multiple-root-layouts)
  - [为同一片段中的部分路由应用布局](#opting-specific-segments-into-a-layout)

## 示例

下面列出几种常见策略的高度概括。最简单的结论是:选一个适合你和团队的策略,并在整个项目中保持一致。

> **须知**:在下面的示例中,`components` 和 `lib` 文件夹只是通用占位名,其命名没有特殊的框架含义。你的项目也可以用 `ui`、`utils`、`hooks`、`styles` 等其他文件夹。

### 把项目文件存放在 `app` 之外

这种策略把所有应用代码放在**项目根目录**的共享文件夹中,`app` 目录只承担路由职责。

### 把项目文件存放在 `app` 内的顶层文件夹

这种策略把所有应用代码放在 **`app` 目录根部**的共享文件夹中。

<Image
  alt="An example folder structure with project files inside app"

### 按功能或路由拆分项目文件

这种策略把全局共享的应用代码放在根 `app` 目录,把更专属的应用代码**拆分**到使用它们的路由片段中。

### 组织路由而不影响 URL 路径

要在不影响 URL 的前提下组织路由,可以创建路由组把相关路由放在一起。圆括号中的文件夹名不会出现在 URL 中(如 `(marketing)` 或 `(shop)`)。

尽管 `(marketing)` 和 `(shop)` 中的路由共享同一 URL 层级,你可以在各自文件夹里添加 `layout.js` 为每组创建不同的布局。这些布局会嵌套在既有的应用布局之内。

### 让特定片段应用布局

要让特定路由应用某个布局,新建一个路由组(如 `(shop)`),把共享该布局的路由(如 `account` 和 `cart`)移进组内。组外的路由(如 `checkout`)不会共享该布局。

### 为特定路由启用加载骨架屏

要通过 `loading.js` 文件为特定路由应用[加载骨架屏](/docs/app/api-reference/file-conventions/loading),可以新建一个路由组(如 `/(overview)`),再把 `loading.tsx` 移进该路由组。

<Image
  alt="Folder structure showing a loading.tsx and a page.tsx inside the route group"
  srcLight="/docs/light/route-group-loading.png"
  srcDark="/docs/dark/route-group-loading.png"
  width="1600"
  height="444"
/>

这样,`loading.tsx` 只作用于 dashboard → overview 页面,而不是所有 dashboard 页面,同时不影响 URL 路径结构。

### 创建多个根布局

要创建多个[根布局](/docs/app/api-reference/file-conventions/layout#root-layout),先删除顶层的 `layout.js`,再在每个路由组里各放一个 `layout.js`。这适用于把应用划分成 UI 或体验完全不同的板块。`<html>` 和 `<body>` 标签需要加到每个根布局中。
